# Paper Review

## Review

Khoja, Wu, Chang and their coauthors propose the Accountable Agents Framework (AAF) as protocol-agnostic infrastructure for connecting an AI agent's otherwise pseudonymous transactions to a verified principal. A directory verifies and registers principals, binds agents to authentication methods, issues verifiable identifiers, and retains the records needed for later attribution. Counterparties can check presentations without contacting the directory for each transaction; an established identity-escrow process permits an agent's principal to be recovered after an incident. The framework deliberately does not decide who bears legal liability, when identification must be mandatory, or which institutions should operate directories. Its contribution is therefore a set of proposed interoperability and accountability properties, not a proof that registered agents will act lawfully.

Appendix A gives this proposal unusually concrete boundaries. Principal identity proofing (PV-1), agent authentication and binding (AG-1/AG-2), holder-bound presentations (PR-2), selective disclosure and unlinkability (PR-5 to PR-7), and offline verification using published directory information (PR-9) describe distinct functions. Legal-person proofing is optional (PV-2): a verified domain, email address, workload or personhood assertion need not resolve to a legally responsible human or organization. The paper also specifies identity escrow (ES-1) and requires each directory to publish a maximum revocation latency (RV-2), rather than describing revocation as instantaneous. These distinctions are valuable because they make the assurance actually supplied by an identifier inspectable instead of assuming that any verified ID has the same legal or operational meaning.

The architectural tension is that a directory is both an attestor and a discretionary institution. It decides which identity evidence suffices, what records to retain, what disclosures are permitted, and when registrations or claims are revoked (DR-1/DR-2). Counterparties separately decide which directories and claims justify access. Thus an ID does not convey a universal trust verdict. It conveys an issuer-specific proposition whose value depends on the counterparty's reliance policy and on the directory's actual adherence to its published practices. Appendix C surveys trust lists and audits as possible coordination mechanisms, but conformity assessment is optional (DR-3). Published practices enable scrutiny; they do not themselves establish independent oversight, fair admission, appeal rights or reliable enforcement of disclosure limitations.

AAF is also precise about an important boundary that its framing can otherwise obscure. Section 3.5 explicitly acknowledges that attributing an agent to a principal does not settle responsibility for harm caused by a provider defect, compromised system or adversarial prompt injection. Appendix D notes that a hijacked agent can still sign a presentation with its legitimate key. The governance implication is that authentication of the acting software and recovery of its principal are evidentiary inputs, not a determination that a particular act was authorized. Principal-attested authorization claims are supported, and optional delegated-agent registration requires attenuation (AG-3), but the core valid presentation requires only an ID (PR-1). A counterparty that accepts that minimum cannot infer transaction-specific permission, current mandate, or compliance with an independently governed execution policy.

The authors have a credible answer to a demand that AAF specify those controls: they explicitly seek a reusable identification foundation compatible with sector-specific authorization and legal regimes. That scope choice is defensible. It does not, however, support treating interoperable attribution as sufficient accountability infrastructure. Where consequential services use the ID as an access condition, the surrounding trust framework must separately prescribe how delegation is validated at the execution boundary, how claims with different issuers and assurance levels are evaluated, which evidence survives an incident, and who can challenge a wrongful suspension or attribution. This requirement follows from the proposed system's own reliance on directory and counterparty discretion, not from an expectation that an identity specification should become a complete liability code.

The privacy model warrants similarly careful treatment. Fresh, unlinkable IDs and pairwise pseudonymous identifiers (PR-8) limit routine correlation by counterparties, while identity escrow preserves a controlled route to attribution. Optional multiparty escrow (ES-2) can distribute the power to reveal identities, but AAF requires neither independent authorization of disclosures nor an appeal mechanism for abusive tracing. A further tension arises from revocation. RV-2 requires a published upper bound, and Appendix C exposes the trade-off between that bound, online visibility and verification cost. A technically conforming design may still permit harmful use during its declared latency, while erroneous or coerced revocation may deny legitimate agents access across several services. More directories reduce dependence on one operator but create incentives for permissive-directory shopping, as the authors acknowledge in Section 3.5.

This paper should be read alongside the archive's *Designing Agent IDs* and *Accountable yet Anonymous AI Agents*. The former maps the option space for identifiers and delegation; the latter examines institutionally split knowledge in an identity-escrow architecture. AAF's increment is a named set of requirements for privacy-preserving principal tracing, including a measurable revocation bound and a directory-practices contract. Its Appendix C is an implementation-options survey, not a reference implementation or cross-directory conformance test. The claimed compatibility of these options therefore remains to be established under adversarial conditions, especially where unlinkability, timely invalidation and historical escrow must hold simultaneously.

The appropriate next evidence is a conformance suite that tests revoked credentials against the published latency, cascaded delegation, stolen keys, false principal binding, wrongful revocation, disclosure authorization and directory migration, while distinguishing cryptographic PASS results from institutional assurance. AAF provides a useful foundation for attributing pseudonymous agent activity without universal identity disclosure. It should be adopted as an attribution profile within governed trust infrastructure, not mistaken for the authority or liability layer that such infrastructure must also supply.

## Key Insight

AAF makes pseudonymous agent-to-principal attribution independently verifiable, but directory-controlled disclosure and revocation cannot establish legitimate delegation or responsibility for a particular action.
